# Presentation workflows

## Contents

Four user-requested procedures for talks and presentation outputs: opening,
slide audit, memorable idea cards, and persuasion structure.

## Usage

Load only for presentation work through `awino-visualize`. Apply the requested
procedure, not all four automatically. Read the user's materials first; reuse
answers already supplied and ask only for missing inputs that affect the result.
Do not invent audience characteristics, findings, slide contents or sources.

## Format

Each procedure states its role, inputs, actions, rules, output and checks.
These are user-supplied Winston-inspired instructions, not verified quotations
or a claim that every rule originated with Patrick Winston or MIT. Verify a
first-party source before making historical attribution in a public artifact.

## Stability

This is an on-demand reference, not a second controller or standing instruction
to override an approved task. Preserve meaning and factual qualifications when
simplifying slides; semantic quality requires review, not just keyword checks.

## 1. Start any presentation right

**Role:** Presentation strategist using the user's Winston-inspired approach.

**Goal:** Capture attention and frame the talk around a clear audience benefit.

**Inputs:** Topic, audience and core idea. Ask for missing values only.

**Actions:**
1. Choose one supported surprising question, bold claim, or vivid scenario.
2. Make the first sentence earn attention without greetings or housekeeping.
3. State the talk's promise within the first 60 seconds.
4. Draft the remainder of a 90-second opening and explain the choices.

**Rules:** Never open with "Today I'll be talking about..."; cut pleasantries;
no jokes or gimmicks. A bold claim still needs evidence. Label imagined scenarios
as hypothetical rather than presenting them as events that happened.

**Output:** A 90-second opening script plus a rationale for the hook, promise,
audience framing and transition.

**Check:** Estimate spoken duration using an explicitly stated speaking rate;
mark the promise's estimated position. Treat timing as estimated until rehearsed.
Do not promise that reading a word count proves a live 90-second delivery.

## 2. Eliminate slide crimes

**Role:** Visual communication editor.

**Goal:** Make slides support the spoken word instead of replacing it.

**Inputs:** Actual slides, screenshots, or a slide-by-slide outline. Request
missing slides rather than inventing an audit of unseen material.

**Actions:** Flag excessive text, missing titles and low contrast; rewrite each
supplied slide around one headline and one visual idea. Move supporting detail
to speaker notes where it remains necessary for accuracy.

**Rules:** One idea per slide; every slide has a title. Slides serve the
audience's eyes while the voice provides the spoken explanation. Do not remove
essential caveats, units, labels or citations merely to reduce word count.

**Output:** Old vs. new breakdown by slide, including observed issue, replacement
headline, visual idea and speaker-note placement; finish with
**Slide Crimes Removed**.

**Check:** Verify every supplied slide is covered. Judge contrast/layout only
from available visuals or measured colors; mark those checks unverified when
only text is supplied. Render changed slides when a suitable tool is available.

## 3. Make ideas unforgettable

**Role:** Memory and rhetoric editor.

**Goal:** Give three core ideas concrete memory cues.

**Inputs:** Three key points; ask for missing points or confirm which three to
prioritize when the choice materially changes the user's message.

**Actions:** For each idea, write an eight-word slogan, propose a concrete visual
anchor, and design one surprising contrast that preserves the source meaning.

**Rules:** No jargon or abstract slogans; prefer concrete language. If a slogan
cannot express the idea accurately, refine the idea rather than inventing a
stronger claim. A proposed symbol is not a claim that an image was generated.

**Output:** Three idea cards, each with **Slogan / Symbol / Surprise / Big idea
sentence**.

**Check:** Count each slogan as eight whitespace-separated words, using plain
words to avoid hyphenation ambiguity; confirm the three contrasts are supported
or explicitly hypothetical. Three-day audience recall is an intended outcome,
not a result proven without audience testing.

## 4. Structure a persuasive talk

**Role:** Rhetoric architect.

**Goal:** Build toward one decision or belief using Situation, Problem,
Implications, Solution (SPIS).

**Inputs:** Existing outline/content, audience, and desired decision or belief.

**Actions:** Map supplied content to the four sections, add explicit transitions,
identify the contribution moment (what this work adds), and write a strong close.

**Rules:** Every section must prepare the next. The final slide is a statement
of value, never merely "Thank You." Retain uncertainties and alternatives needed
for an honest decision; do not invent urgency or a contribution.

**Output:** Full structured outline plus a rewritten closing statement and final
slide headline.

**Check:** All four sections are present, the contribution is distinguishable
from background, and the close reinforces the single intended decision/belief.

## Evaluation examples

- Given a topic/audience/core idea, requesting an opening returns the script and
  rationale without asking for the same inputs again.
- Given text-only slides, the audit covers each slide but does not claim it
  measured contrast or inspected rendering.
- Given three core ideas, produce exactly three cards and eight words per slogan;
  do not claim audience recall has been measured.
- Given a talk outline, return the four-part arc and a value-ending close;
  requesting only a chart must not trigger a talk script.
